# replication/: multi-model replication v1 (in progress)

Question: do the Qwen2.5-7B findings hold in Llama-3.1-8B-Instruct and Gemma-2-9B-it? Each model builds its **own** conversations. The findings being tested are:

- native and pasted histories are linearly separable;
- a shared native-minus-pasted direction exists;
- adding that direction moves answer length with its sign.

**Status (2026-11-27):** running on one RTX 4090. Results will be added under `reports/replication-v1/` when the runs finish.

## Design in one screen

- **Histories:** each model answers the 240 v2.1 candidate cases itself. A history is admitted only if every turn ends with the end-of-turn token and passes the v2.1 rule check. At most 30 are admitted per rule.
- **Depths:** states are captured at round(L·k/7) for k = 0..7, which matches Qwen's 0, 4, …, 28.
  - Llama: 0, 5, 9, 14, 18, 23, 27, 32.
  - Gemma: 0, 6, 12, 18, 24, 30, 36, 42.
- **Steering (primary, k = 4, the relative depth of Qwen layer 16):** Llama layer 18, Gemma layer 24. The vector is the cross-fitted mean B − C, added at alpha 1.
- **Open units:** the same 81 open-ended units as transfer v1, with the assistant turns regenerated by each model.
- **Primary tests, per model (97.5% intervals):**
  - H1: length effect on v2.1-style ordinary units (L_sign, L_random).
  - H2: the same on the open units.
  - Decision rule: *replicates* if both lower bounds are above 0; *absent* if L_sign's interval lies inside ±0.05; otherwise *inconclusive*.
- **Shallow follow-up (k = 2: Llama 9, Gemma 12, Qwen 8):** registered separately (`protocol_shallow.json`) after the Llama k = 4 result was seen. The reason is stated in the protocol. k = 4 remains the primary result.
- **Same-pipeline Qwen run:** Qwen2.5-7B also goes through this exact pipeline, so all three models are compared like for like.

## Files

**Registered files.** Hashes are in `data/replication_v1/registration.json` and `registration_shallow.json`, so do not edit them. Amendment 1 was made before any generation; it is described in the registration's `review_note`, and the superseded registration is kept.

| File | Role |
|---|---|
| `protocol.json`, `protocol_shallow.json` | The designs. |
| `engine.py` | Model-agnostic GPU engine: family settings (`FAMILIES`), chat formatting for B, C, C_qa and C_json, cached greedy decoding with explicit positions, hidden-state capture, steering hooks, and chunked teacher-forced log-probs. |
| `build_open.py` | Extracts the 81 open units from the transfer inputs. |
| `run.py` | Five resumable phases: histories, baseline, directions, steering, open units. |
| `shallow.py` | k = 2 follow-up. It reuses a finished run and repeats only the steered conditions. |
| `freeze.py`, `freeze_shallow.py` | Write the registrations. |
| `summarize.py` | CPU. Gives the H1/H2 decisions, probe accuracy by layer, direction checks and behaviour. Needs numpy and scikit-learn. |
| `summarize_shallow.py` | CPU. Gives the H1s/H2s decisions, with k = 2 and k = 4 side by side on the same units. Written before any shallow output existed. |

```bash
python replication/run.py --family llama31 --model <model dir> --v21 <v2.1 run> --open-units <open_units.jsonl> --registration data/replication_v1/registration.json --out runs/run-llama31
python replication/shallow.py --family llama31 --model <model dir> --run runs/run-llama31 --v21 <v2.1 run> --open-units <open_units.jsonl> --registration data/replication_v1/registration_shallow.json
python replication/summarize.py --run runs/run-llama31
python replication/summarize_shallow.py --run runs/run-llama31
```

Both GPU scripts take `--resume` (skips finished units) and `--smoke N` (tiny-model check, no registration).
